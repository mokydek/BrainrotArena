# 🧠 Brainrot Arena

Сайт с розыгрышами брейнротов и лидербордами стримеров (Next.js 16 + Supabase, деплой на Vercel).

- **Слева и справа — лидерборды стримеров**, которые оплатили показ. Аватар, ник, галочка, подписчики и статус эфира подтягиваются по ссылке на TikTok (также YouTube, Twitch, Kick; Instagram и прочие — вручную). **Кто сейчас в эфире — всегда сверху**, с плашкой `Live` и числом зрителей.
- **Плюсик у лидербордов видят только админы** → вставляешь ссылку → «Загрузить» → данные подтягиваются → «Добавить». Можно указать срок показа (1/3/7/14/30 дней, до даты или навсегда), сторону, вручную поправить имя/аватар и статус эфира.
- **По центру — розыгрыш**: название, приз, картинка брейнрота (загрузка файла или ссылка), любое число участников (или лимит), таймер (быстрые кнопки, своя длительность или точное время; `-1/-10/+1/+10` минут прямо на странице). Когда таймер заканчивается, встроенный **provably-fair рандомайзер** выбирает победителя — у всех на экране крутится лента никнеймов и показывается победитель.
- **Никнейм закреплён сверху**, сохраняется на устройстве, **одинаковых ников быть не может** (без учёта регистра).
- Страница **Verify History** — любой может пересчитать результат прямо в браузере.
- Языки EN / RU.

## Деплой (≈5 минут)

Адрес Supabase-проекта (`vuknddvhpwkyjvrypaql`) и его публичный anon-ключ уже вшиты в код, их задавать не нужно.

1. **Таблицы в Supabase**: открой [SQL Editor](https://supabase.com/dashboard/project/vuknddvhpwkyjvrypaql/sql/new) → вставь всё содержимое [`supabase/schema.sql`](supabase/schema.sql) → **Run**. Скрипт можно запускать повторно — он ничего не ломает.
2. **Vercel** → Add New → Project → импортируй репозиторий `BrainrotArena` (фреймворк определится сам — Next.js).
3. Перед Deploy открой **Environment Variables** и добавь две переменные:

   | Переменная | Значение |
   |---|---|
   | `SUPABASE_SERVICE_ROLE_KEY` | Supabase → Project Settings → API Keys → `service_role` (secret). Никому не отправляй, только в Vercel |
   | `ADMIN_PASSWORD` | придумай длинный пароль для админки |
   | `CONTACT_URL` *(необязательно)* | ссылка для карточки «ТВОЙ СТРИМ ЗДЕСЬ» |

4. **Deploy**. Если переменные добавил после деплоя — Deployments → Redeploy.

Готово: заходишь на `https://твой-сайт/admin`, вводишь пароль → у лидербордов появляются «+», в центре — кнопка «Новый розыгрыш».

Другой Supabase-проект: задай `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_ANON_KEY` — переменные всегда важнее вшитых значений. Если добавить `POSTGRES_URL_NON_POOLING` (Supabase → Connect), таблицы можно создать кнопкой «Создать таблицы» в `/admin` вместо шага 1.

## Обновления базы

Если таблицы уже созданы раньше, для «Условий участия» выполни один раз в [SQL Editor](https://supabase.com/dashboard/project/vuknddvhpwkyjvrypaql/sql/new):

```sql
alter table public.contests add column if not exists conditions text;
```

(то же лежит в `supabase/migrations/002_contest_conditions.sql`; полный `schema.sql` тоже можно перезапустить).

В шапке показывается, сколько людей сейчас на сайте (каждая открытая страница отмечается раз в 20 секунд, считаются все за последние 90 секунд). Нужен SQL из `supabase/migrations/003_online_counter.sql` (или перезапуск `schema.sql`) — без него счётчик просто скрыт.

## Как это работает

- **Живые обновления** — Supabase Realtime (участники, победитель, стримеры обновляются без перезагрузки), плюс резервный опрос каждые несколько секунд.
- **Статус эфира** проверяется не чаще раза в минуту на стримера (запрос делают сами посетители, сервер атомарно «забирает» устаревшие записи, чтобы не дублировать работу). Аватар/ник/подписчики обновляются раз в 12 часов, аватар копируется в Supabase Storage (ссылки TikTok CDN протухают).
- Если TikTok временно не отдаёт данные — стримера всё равно можно добавить вручную, а статус эфира переключить на «Всегда в эфире».
- **Честность розыгрыша**: при создании генерируется секретный `server seed`, публикуется только его SHA-256. После окончания:
  `client seed = sha256("0:ник\n1:ник…")`, `билет победителя = HMAC-SHA256(server seed, "ID:client seed")[0..13 hex] mod N`.
  Жеребьёвка идёт внутри базы (`draw_contest`), после неё seed раскрывается и проверяется на `/history`.
- **Безопасность**: публичный ключ может только читать стримеров/розыгрыши/участников; все изменения — через API с проверкой админ-сессии (подписанная httpOnly-кука) или токена игрока. Токены игроков хранятся только в виде хэша.

## Структура

```
src/app/            страницы (/, /admin, /history) и API (src/app/api/*)
src/components/     интерфейс (лидерборды, розыгрыш, модалки, фон)
src/lib/social/     парсинг TikTok / YouTube / Twitch / Kick
src/lib/fair.ts     проверка честности розыгрыша (браузер + сервер)
supabase/schema.sql таблицы, RLS, функции (join/draw), бакет media
tests/              unit, API и браузерные e2e-тесты
```

## Локальная разработка и тесты

```bash
npm install
cp .env.example .env.local   # заполни ключи Supabase
npm run dev
npm run test:unit
```

Полный прогон (нужны локальные Postgres 15+ и бинарник [PostgREST](https://github.com/PostgREST/postgrest/releases)):
`cd tests/e2e && npm i && cd ../.. && POSTGREST_BIN=/path/to/postgrest tests/run-all.sh` — поднимает локальную копию API Supabase, собирает сайт и прогоняет API-тесты и браузерные сценарии (админ + 3 игрока, десктоп и мобильный).
